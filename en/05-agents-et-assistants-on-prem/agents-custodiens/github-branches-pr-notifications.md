Git is the natural guardrail for a custodian agent. It turns a risky action ("the agent modifies the vault") into a reversible proposal ("the agent opens a branch with a diff").

## Branch convention

Recommended format:

```text
agent/YYYY-MM-DD/<short-objective>
```

Examples:

- `agent/2026-06-04/link-audit`
- `agent/2026-06-04/refresh-nvlink`
- `agent/2026-06-04/lexicon-backlog-cleanup`

## Minimum content of an agent PR

A PR generated by an agent should include:

- readable summary;
- modified files;
- external sources consulted;
- commands executed;
- limits and assumptions;
- human review checklist.

> [!tip] Good signal
> A good agent PR should let you reject the proposal without losing information: even if the diff is not merged, the report should remain useful.

## Notifications

Possible channels:

- GitHub PR;
- email;
- Slack/Matrix/Discord webhook;
- Markdown file in `.agents/vault-maintenance/runs/`.

The channel matters less than the rule: **notification does not equal validation**.

## Anti-patterns

- single `agent-work` branch reused indefinitely;
- direct commit to `main`;
- PR without sources;
- notification that automatically triggers merge;
- agent that reruns a superseded task because an old plan still has TODOs.
